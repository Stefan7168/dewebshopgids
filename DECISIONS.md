# Decisions

Record every decision that deviates from or adds to the plan. Newest first. Format: date, decision, reason.

- 2026-10-28: Pages (task 18). Category pages use one flat route, `/categorie/[slug]`, for the parent `wonen` and its sub-categories (plan: `/categorie/[slug]/[sub]`); a parent page lists the shops of its direct sub-categories too. Reason: one template, and `/api/revalidate` already accepts this shape. Any category page with fewer than 5 shops is `noindex`. Public reads use the anon key without cookies (`lib/shops/data.ts`, `'use cache'`, tag `shops`, hourly fallback); `/api/revalidate` now also expires the `shops` tag. Earned sub-scores and quotes come from the internal `scores` and `shop_signals` tables through the service client in `lib/shops/evidence.ts` (same pattern as `/go/`), filtered by `lib/shops/evidence-rules.ts`: only the newest score's run, only verified `llm` quotes, only sub-scores with points, never `marketplace_pattern` or `dropship_indicators`. Without `SUPABASE_SERVICE_ROLE_KEY` the page shows no sub-scores rather than unproven ones. `score_label = 'audit_required'` shows "In beoordeling" and no number; the publish job (later task) clears it once the auditor agrees. Ranking: numbered shops by score, then "In beoordeling", then labelled shops, ties by name; the disclosure text is built from `weights.ts` so it cannot drift. `partialPrefetching` is on because Cache Components refuses an empty `generateStaticParams` and CI builds have no database: unknown slugs serve the shell, then cache the URL render. Side effect: page metadata streams after `</head>`, so Lighthouse SEO reads 90 on shop and category pages (meta description not in head); Google renders it. Canonical URLs use `https://dewebshopgids.nl`.
- 2026-10-28: Ops Watchdog and digest (task 17b). The Watchdog is one routine at 05:30, 11:30, 17:30 and 23:30 Amsterdam (`agent_ops`). `start` exits with code 4 when no check failed in the last 7 hours and it is not the Sunday 17:30 run, but still writes an `ok` run row so the gap check sees it alive. It pauses an agent by setting `enabled.<agent> = false` and `paused_until.<agent>` 48 hours ahead, and queues an `ops_pause_alert` owner email in the same transaction. It cannot pause itself. The health job (`pipeline` role) lifts a pause once `paused_until` has passed and the run has no failed check; a disable without `paused_until` is a human decision and stays. The digest (`digest.yml`, Sunday 18:00 Amsterdam) queues one `weekly_digest` owner email per ISO week, in Dutch, with runs per agent, schedule gaps, pauses, spend, escalations, PRs merged and open, and gate settings. It folds in the newest `digest_summary` row (marked sent so it is not mailed twice) or prints "summary missing". Chain metrics, screenshots and incidents are added when their data exists (tasks 18+). Sending is the email sender's job (Resend, later task).
- 2026-10-28: Ops jobs (task 17a) are plain code on GitHub Actions as the `pipeline` role. `health.yml` runs every 6 hours (`/api/health` via the `HEALTH_URL` repo variable, Vercel and Supabase status pages, failed runs in 24 hours, spend against budget: warn at 80%, fail at 100%). `schedule-gaps.yml` and `escalations.yml` run every 3 hours, not hourly. Reason: each run bills at least one Actions minute; hourly jobs would use about 1,440 of the 2,000 free minutes per month. The gap job syncs `agent_schedule` from every `agents/*/agent.json` with a schedule plus the code jobs listed in `scripts/ops/health.ts`, and queues at most one `ops_gap_alert` email per agent per 24 hours; an agent that never ran counts as late. `health_endpoint` reports `warn` until `HEALTH_URL` is set, because Vercel deployment protection blocks Actions until the custom domain exists. Escalation issues get a header that marks the text as untrusted data, and `@` mentions are neutralised so scraped text cannot notify people.
- 2026-10-28: The Score Auditor (task 16) is a routine (daily 07:00 Amsterdam, rubric prompt `a1`). Its tool computes the total from the auditor's five sub-scores using the pipeline's cap and floor, so the two totals compare like for like. Verdict: within 10 points `agree`, within 20 `review`, otherwise `escalate`. Any marketplace or dropship disagreement escalates. Escalations are `agent_escalations` rows (`agent-proposed`), filed as GitHub issues by `escalations.yml` in task 17. State chain: `start` exits with code 5 unless a `score_runs` row in the last 36 hours is `ok`; the routine retries hourly, at most 3 times. Holdout: up to 10 published shops per 7 days that had no check in the last 28 days. `finish` adds the run's MAE to `agent_runs.summary`.
- 2026-10-28: The nightly pipeline (task 15b) is one workflow, `pipeline.yml`, that runs `scripts/pipeline/nightly.ts` in this order: promote candidates, collect score batches, crawl, domain age, submit a new batch. Each step writes its own `agent_runs` row, and a failing step does not stop the next one. The run ends with a `health_checks` row (`failed_runs`, ok or fail). A batch under 80% quote match fails the collect step, so the health row turns `fail`. `/api/health` returns 503 when the newest `score_runs`, `agent_runs` or `health_checks` row is missing or older than 48 hours. It reads with the service client and returns only timestamps and statuses. `/api/revalidate` accepts only a Bearer `REVALIDATE_SECRET` and site paths (`/`, `/webshop/*`, `/categorie/*`, `/gids/*`, `/over`). Domain age: at most 30 shops per night. A `.nl` domain without a WHOIS answer is retried later.
- 2026-10-28: Crawl step (task 15a) fetches home, about, contact, up to 3 product pages linked from home, `/sitemap.xml` (max 10 sitemaps) and keurmerk certificate pages, all through `fetchPolite()`, with 4 shops in parallel (politeness is per domain inside the shared fetcher). Max 60 shops per night: never-crawled shops first, then 1/30 of the rest, oldest crawl first. Rule facts go to `shops` and append-only `shop_signals` (`has_kvk`, `product_count`, `keurmerk_verified`). An existing `contact_email` is never overwritten. Domain age (SIDN and Wayback) is its own slower step in 15b.
- 2026-10-28: Scoring (task 14b) uses `@anthropic-ai/sdk` 0.134.0, the newest release at least 14 days old (1.x is under a week old); move to 1.x once it has aged. Haiku 5.5 runs with `effort: low` and structured outputs. Pages are labelled P1 to P5 in the prompt, and the model names a page id instead of a URL, so a quote is always checked against the exact text it was given. Only one batch is open at a time: the next submit waits until the open batch is collected. A batch under 80% quote match keeps its `shop_signals` rows for the audit trail but writes no `scores`. Batch cost is added to `agent_settings.month_spend_usd`, which `budgetGuard()` reads.
- 2026-10-28: Score maths v1 (`lib/scoring/weights.ts`) fills in the plan's rubric: Maker 30 for own production, 20 for own brand; Focus 20/12/4/0 for single niche, few related, broad, everything; Identity 7 named owner, 7 address, 6 KvK; Origin 4 handmade, 3 own atelier, 3 made in NL, 2 made in EU (only without NL), capped at 10. Unknown counts as 0 points. The keurmerk floor of 25 also applies to pattern-capped shops (25 stays under the cap of 30). Quotes with a person's name or a street address are stored redacted (`[naam]`, `[adres]`, `[postcode]`) instead of dropped, so `has_named_owner` and `has_address` can still earn points with verified evidence and no personal data stored. Reason: the plan drops such quotes, which would make the identity points impossible to earn.
- 2026-10-28: The six rule extractors of task 13 ship in one PR as separate modules under `scripts/pipeline/extract/`, each with its own fixture tests. Reason: pure functions with no shared state; wiring them into the nightly crawl happens in task 15. Domain age shows the Wayback first-capture year, and only when SIDN WHOIS and Wayback agree within 2 years.
- 2026-10-28: `/go/[slug]` uses the service-role client server-side (it needs `affiliate_url`, which anon cannot read, and inserts into `clicks`). Device class comes from the user agent at request time; the UA itself is never stored. Country comes from Vercel's `x-vercel-ip-country` header. Footer identity lives in `lib/site.ts` and says "KvK-inschrijving in behandeling" until Stefan's KvK number exists. `/privacy` and `/informatie-voor-webshops` are already exempt from Basic Auth for the Daisycon review.
- 2026-10-28: Migration 0007 seeds the launch category `wonen` (Wonen & interieur) with 7 provisional sub-categories. The plan's "0007 guide_issues" becomes the next free number in phase 3. Shop Scout tools only accept domains present in `source_lists`, cap proposals at 25 per 24 hours in code, and wrap source names in the untrusted-data block.
- 2026-10-28: Task 12 (`fetchPolite()`) is built before task 10, because the source list import in task 10 fetches pages and must use it. robots.txt follows RFC 9309: 4xx means allow all, 5xx or network error means disallow all. Crawl-delay is honoured up to 30 s. Uses `robots-parser` 3.0.1 (MIT).
- 2026-10-28: Agent roles are created NOLOGIN without passwords (plan: `create role ... with login password`). `scripts/agents/set-role-password.ts` enables one role and prints a fresh password once. Reason: no password may live in a migration or the repo; the same script re-enables a role after the kill switch.
- 2026-10-28: The publish trigger blocks every role except `pipeline`, including `service_role` and `postgres`. Ops alert emails use the fixed recipient `owner`, resolved from `OWNER_EMAIL` at send time. The Dispute Handler can set `agent_replied` or `awaiting_human` but not `resolved`; code resolves. Role tests run in CI on local Postgres; on Supabase the MCP user cannot `SET ROLE` to agent roles, so there only the publish guard and NOLOGIN state were checked.
- 2026-10-28: Migrations 0002 to 0005 (plan tasks 5 to 8) ship in one PR with one file each. Reason: they are plain internal tables with the same RLS pattern; one review instead of four. `commissions` adds `network_transaction_id` (unique per network) so the Daisycon import is idempotent. `subscribers` stores no email address: Resend holds it.
- 2026-10-28: `kill-switch.yml` runs on `workflow_dispatch` only, no cron. The `/admin` kill switch (later task) sets `agents_enabled = false` and dispatches the workflow. Reason: a 15-minute cron on a private repo would use about 2,900 of the 2,000 free Actions minutes per month. The kill job also sets `agents_enabled = false` itself, so the soft guards agree with the hard stop.
- 2026-10-28: Agent jobs and the kill switch use the `postgres` npm client over a direct or Supavisor connection string (`DATABASE_URL`, `prepare: false`), not supabase-js. Reason: per-agent login roles need a real Postgres connection; the REST API only knows anon and service keys.
- 2026-10-28: Migration 0001 also lets anon read `categories` (plan: anon reads only `shops_public`). Reason: categories are public navigation with no private data. Anon reads `shops` only for published rows and only public columns (column grant), so `contact_email` and `affiliate_url` never leave the server. Text columns with `check` constraints instead of Postgres enums, so agents can extend value lists in a plain migration.
- 2026-10-28: SQL tests run on a local Postgres with a small Supabase bootstrap (`supabase/tests/bootstrap_local.sql`, `scripts/db/test.sh`) and in CI against `postgres:17`, instead of `supabase db reset`. Reason: no Docker-in-Docker needed; same check ("reset clean" plus role tests).
- 2026-10-28: Reviewer and label guard run on `pull_request_target`; the Reviewer checks out the PR head into `./pr-head` as data and has no shell besides `gh pr` commands. Reason: secrets live in the `production` environment bound to `main`; on `pull_request` a PR could rewrite the workflow and read them. The Reviewer also runs on `opened` (non-draft), since a PR opened ready never fires `ready_for_review`.
- 2026-10-28: The Developer agent uses the Claude GitHub App token (OIDC), not `GITHUB_TOKEN`. Reason: PRs opened with `GITHUB_TOKEN` do not trigger CI.
- 2026-10-28: `claude-code-action` pinned to commit `8c3fd98` (v1.0.264), above the 1.0.74 floor from CVE-2026-47751.
- 2026-10-28: npm instead of pnpm (plan section 13). Reason: the official starter ships npm and a lockfile; one less tool for agents.
- 2026-10-28: Supabase Auth login is limited to emails in `ADMIN_EMAILS`, and the starter's sign-up pages are removed. Reason: the site has no public accounts; only Stefan uses `/admin`.
- 2026-10-28: Basic Auth lives in `proxy.ts` (Next.js 16 replaced `middleware.ts` with `proxy.ts`). Public exemptions: `/over`, `/api/health`, `/api/revalidate`. Reason: plan task 1 check (401 on `/`, 200 on `/over`); health must stay reachable for the uptime monitor.
- 2026-10-28: Started from the official `vercel/next.js` `examples/with-supabase` starter, dependencies pinned to exact versions (Next 16.4.3, @supabase/ssr 0.12.7, @supabase/supabase-js 2.118.0). Reason: the starter uses `latest`, which makes builds non-reproducible for agents.
